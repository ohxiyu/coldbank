# ColdSigner v0.1 Product Requirements Document

| Field | Value |
|---|---|
| Status | Development baseline |
| Product stage | Pre-alpha → testnet alpha |
| Platform | iPhone, iOS 16+ |
| Primary language | Simplified Chinese first; strings must be localization-ready |
| Primary integration | Sparrow Wallet |
| Security posture | Offline software signer; not a hardware-wallet equivalent |

## 1. Product definition

ColdSigner turns a spare iPhone into a dedicated, open-source Bitcoin signer. The online coordinator constructs and broadcasts transactions; ColdSigner only creates or restores keys, exports public wallet data, reviews unsigned PSBTs, signs locally, and returns signed PSBTs over optical QR transfer.

The v0.1 promise is narrow:

> A user can create or restore one BIP84 single-signature wallet on an offline iPhone, export its watch-only data to Sparrow, review an imported PSBT, sign it after local authentication, and return a standards-based animated QR without any network path in the app.

## 2. Goals and success criteria

### Product goals

1. Make the air-gapped signing loop understandable without requiring command-line knowledge.
2. Show enough transaction information for a user to detect a changed recipient, amount, fee, or unrecognized output.
3. Keep secret-bearing operations local, explicit, and short-lived.
4. Establish reproducible interoperability fixtures before expanding wallet or script support.
5. Publish an honest security model that distinguishes a hardened offline phone from dedicated signing hardware.

### v0.1 release gates

- 100% pass on the Sparrow BIP84 mainnet/testnet fixture suite.
- Import and export `ur:crypto-psbt` payloads larger than one QR frame with loss, duplication, and out-of-order frames.
- Reject all unsupported script, network, sighash, or incomplete-UTXO test vectors with a user-readable reason.
- No networking frameworks or known network API symbols in application sources or linked first-party code.
- No secret-bearing values in logs, crash text, clipboard, screenshots generated by tests, or backups.
- Unit coverage for policy and parsers ≥ 90%; overall core-domain coverage ≥ 80%.
- Two-person review for every change touching key storage, derivation, PSBT policy, signing, or QR decoding.
- Testnet soak: at least 50 successful round trips across two supported iPhone models and three PSBT sizes.

Adoption metrics such as downloads or value signed are explicitly not v0.1 success metrics.

## 3. Users and jobs

### Primary user

A self-custody Bitcoin user who already understands seed backups and uses Sparrow, BlueWallet, or Nunchuk as an online coordinator. They have a spare iPhone that can be erased and kept offline.

### Core jobs

- Create a new signing key without sending it to another device.
- Restore a known BIP39 seed on a replacement offline device.
- Export public wallet information without exposing private material.
- Understand exactly what an unsigned transaction will do.
- Sign and transfer the result back without cable, NFC, cloud, or network.
- Irreversibly wipe local signing material when retiring the device.

### Not the target user in v0.1

- A first-time Bitcoin user who needs custody education.
- A user who needs multisig, Taproot, Miniscript, CoinJoin, Lightning, altcoins, or transaction construction.
- A user who expects protection against a fully compromised iOS device or hostile supply chain.

## 4. Scope

### P0 — required for v0.1

#### Device and onboarding

- First-launch explanation of offline requirements and limitations.
- Require device-owner authentication availability before wallet creation or restore.
- Create a fresh wallet or restore from 12/24 BIP39 words.
- Generate entropy with the OS CSPRNG through the selected Bitcoin library; never with app-authored randomness.
- Force backup acknowledgement and randomized word verification before activation.
- One wallet per app installation.

#### Wallet profile

- Bitcoin BIP84 native SegWit single signature only: `m/84'/coin_type'/0'`.
- Mainnet production profile; testnet/signet exposed only in Developer Mode before beta.
- Display wallet name, master fingerprint, network, script type, and account path.
- Export public descriptor with origin information and checksum.
- Export account extended public key as text/static QR for coordinators that require it.
- Never display or export xprv except the explicit mnemonic backup flow.

#### PSBT transport and policy

- Scan animated BC-UR v2 `ur:crypto-psbt`.
- Show scan progress and allow cancellation without retaining partial data.
- Parse PSBT v0 only.
- Require every input needed for fee calculation and signature verification to contain valid UTXO data.
- Require input derivation metadata to match the active wallet.
- Support only P2WPKH wallet inputs and `SIGHASH_ALL` in v0.1.
- Reject mixed networks, unsupported scripts, Taproot fields, malformed maps, duplicate keys, excessive sizes, and ambiguous ownership.
- Bound QR payload size, input/output count, derivation depth, and decode work.

#### Transaction review and signing

- Display network, recipient outputs, recognized change, total outgoing amount, miner fee, fee rate, input count, output count, and locktime.
- Never hide an output. Unknown wallet-like outputs remain recipients and receive a warning.
- Verify claimed change by deriving the path and matching the script; do not trust PSBT labels alone.
- Require a review confirmation, hold-to-sign gesture, and device-owner authentication.
- Sign only inputs proven to belong to the active wallet.
- Return the signed PSBT as animated `ur:crypto-psbt`; the coordinator finalizes and broadcasts.
- Clear decoded and signed transaction state after timeout, completion, backgrounding, or cancellation.

#### Local security controls

- App lock on launch/foreground and after an inactivity timeout.
- Seed encrypted at rest using a random data-encryption key protected by a `ThisDeviceOnly` Keychain item and device-owner access control.
- Secret file excluded from device backups and protected with complete file protection.
- No clipboard actions for mnemonic, seed, xprv, or decrypted PSBT details.
- No telemetry, analytics, ads, crash upload, remote config, browser, deep links, or network client.
- Best-effort screen-capture warning and privacy cover when backgrounded; UI must state iOS cannot guarantee screenshot prevention.
- Destructive wipe with typed confirmation and device-owner authentication.

### P1 — after v0.1 baseline

- BIP39 passphrase with explicit hidden-wallet safety flow.
- BIP86 Taproot key-path spending.
- Multisig and BSMS wallet configuration.
- PSBT v2.
- `crypto-account` / `crypto-output` registry exports beyond the minimum Sparrow route.
- Multiple wallets/accounts.
- Duress wallet/PIN, dice entropy, SeedQR, SSKR, NFC, file import, descriptor import.
- App binary reproducibility and signed release attestation.

### Explicitly out of scope

- Network synchronization, balance lookup, fee estimation, exchange rates, transaction construction, broadcast, address book, cloud backup, iCloud Keychain sync, remote support, firmware claims, anti-tamper claims, and protection from a compromised OS.

## 5. End-to-end user flows

### Flow A — create and pair

1. User erases/prepares a spare iPhone, installs a verified build, disables radios, and opens ColdSigner.
2. App explains the threat boundary; user completes the offline/device-passcode checklist.
3. User selects **Create new wallet**.
4. App generates 12 or 24 words; user records them offline.
5. App challenges randomly selected word positions and activates the wallet only after success.
6. Home shows **Scan transaction**, **Export watch-only wallet**, and **Security**.
7. User selects Sparrow format and scans the public descriptor/account QR into Sparrow.
8. Both devices show the same master fingerprint; user confirms it out of band.

### Flow B — restore

1. User selects **Restore existing wallet**.
2. User chooses 12 or 24 words and enters them using a local word-list keyboard.
3. App validates checksum locally and shows network, BIP84 path, and fingerprint.
4. User confirms the fingerprint against the coordinator or backup record.
5. App encrypts the seed locally and enters Home.

### Flow C — review and sign

1. Online coordinator displays an unsigned `ur:crypto-psbt`.
2. User taps **Scan transaction**; ColdSigner reconstructs and validates the payload.
3. Any policy failure stops the flow before the review screen.
4. Review shows all recipients first, then change, outgoing total, fee, fee rate, and technical details.
5. Warnings must be individually visible and cannot be dismissed by scrolling past them.
6. User holds **Hold to sign**, then completes device-owner authentication.
7. ColdSigner revalidates the immutable transaction digest immediately before signing.
8. App signs owned inputs and displays the signed PSBT as animated QR.
9. Coordinator scans, finalizes, and broadcasts; ColdSigner never reports “broadcast success.”

### Flow D — wipe

1. User opens Security → Wipe signer.
2. App explains that the local wallet cannot be recovered without the external backup.
3. User types `WIPE`, authenticates, and confirms.
4. App deletes the encrypted seed, wrapping key, cached public profile, partial QR state, and UI snapshots.
5. App returns to first launch. The UI states that flash-storage deletion is best effort and device erasure is recommended for retirement.

## 6. Transaction policy

Signing is fail-closed. A PSBT is signable only when all conditions hold:

1. It is valid PSBT v0 within configured size/count limits.
2. The unsigned transaction and all maps are internally consistent.
3. Every input has sufficient UTXO information to compute amounts and signatures.
4. At least one input belongs to the active wallet, and every input presented as owned has a verified origin/path/script match.
5. The network and supported BIP84 policy match the active wallet.
6. No unsupported sighash, script, Taproot, proprietary behavior, or ambiguous finalization field is present.
7. Total input is not less than total output, fee is computable, and values do not overflow.
8. Every output is classified as verified change or recipient; classification is displayed.
9. The review digest equals the digest rechecked immediately before signing.

Policy thresholds are constants with tests, not hidden UI heuristics. Initial proposed limits:

| Limit | Initial value |
|---|---:|
| Encoded PSBT | 2 MiB |
| Inputs | 200 |
| Outputs | 200 |
| QR fragments retained | 2,000 |
| Derivation path components | 10 |
| Signing inactivity timeout | 60 seconds |
| App auto-lock | 2 minutes |

These values require profiling on the oldest supported device before release.

## 7. Error model

Errors use a stable code plus plain-language remediation. They never include seeds, extended private keys, raw PSBTs, signatures, or full addresses in logs.

| Class | Example | User action |
|---|---|---|
| Transport | QR is incomplete or wrong UR type | Resume scan or restart |
| Parse | Malformed/oversized PSBT | Recreate in coordinator |
| Policy | Unsupported script or sighash | Use supported BIP84 wallet |
| Ownership | No matching input or invalid derivation | Check selected wallet/fingerprint |
| Review | Fee unavailable or output ambiguous | Signing blocked; recreate PSBT |
| Authentication | Device authentication failed | Retry; never downgrade |
| Signing | Library refused signature | Signing blocked; preserve no partial output |

## 8. Product copy constraints

Use “offline signer” or “air-gapped software signer.” Do not claim:

- hardware-wallet equivalence;
- Secure Enclave secp256k1 signing;
- absolute air-gap, screenshot prevention, secure deletion, tamper resistance, or jailbreak detection;
- audited or production-safe status before independent review.

## 9. Open questions before beta

- Final distribution path: App Store, TestFlight, reproducible sideload, or multiple channels.
- Private security-reporting address and PGP key.
- Whether the default wallet is 12 or 24 words; cryptographic strength is sufficient at 12, but user expectations differ.
- Exact BlueWallet and Nunchuk public-wallet import formats to promote from experimental to supported.
- Oldest device used for performance, camera, and memory release gates.
- External audit scope and funding.
